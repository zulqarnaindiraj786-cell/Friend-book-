# Home story expiry demand

Previously Home persisted an expiry anchor indefinitely and the Worker materialized every matching story before authorization and paging. Old expired stories could consume successive three-story pages. On a visible Home demand the client now reuses an account-scoped anchor for 120 seconds and then advances it; there is no timer or background refresh. Explicit refresh still clears the anchor. More on an expired window restarts at the current head, and in-flight pages remain single-flight and generation guarded. A cached page uses the same 120-second maximum age. These Android changes are not in the installed APK.

The Worker recognizes the ordinary expiry-ordered story rail query, seeks a new expiry-and-ID index, merges a bounded set of unusual expiry encodings, and checks the existing live story ACL before returning a full page. It may scan more candidates to replace denied rows; the limit is not a D1 billed-read ceiling. Unknown cursor forms, missing indexes, malformed rows, or more than 64 unusual rows use the existing complete evaluator, not a partial result. Non-ASCII IDs and nonstandard timestamp values preserve JavaScript ordering through the exception merge. Same-timestamp cursors use a separate indexed equality/ID seek to avoid traversing the whole tie group; rows strictly later than the expiry anchor are then sought separately.

Local SQLite tests compare pages to the old evaluator across actors, privacy, cursor boundaries and unusual values; also cover revocation, errors, old schema and overflow. Explain plans assert expiry and tie ID seeks without an ordering temp tree. A local 1,000-row tie experiment showed the old expiry-only index visited 1,000 rows before a four-row head; the expiry+ID index visited four for the head. This is a local SQLite observation, not Cloudflare billed-read or device evidence. Index creation has a one-time cost, and the additional index can add story write maintenance. No claim of a daily quota guarantee or production savings is established. Author-scoped StoryViewer queries and hashtag all-match sorting remain outside this change.
