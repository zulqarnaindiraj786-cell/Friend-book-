# Author-scoped story pages

StoryViewer asks for ten stories for one author, ordered by document ID, and locally filters expired/inaccessible stories. The old server path loaded all stories for that author before applying the cursor and page limit. The existing author index orders by creation time before ID and cannot seek this page.

The new ordinary-author path seeks `(authorId, doc_id)` in ascending ID order, reads progressively as needed, and applies the same current canonical ACL and viewer projection before filling a page. It checks decoded `authorId` equality, because SQLite's JSON extraction can render an array or object as a string. An author-scoped sparse exception index sends unusual Unicode/malformed IDs to the original complete evaluator; unusual query forms or missing indexes also fall back. It never treats an authorization failure as permission to return a partial unfiltered page. All-denied authors and unusual-data fallback can still scan many rows; page size alone is not a D1 billed-row bound. The client continues showing only active stories, but expired stories can still occupy author pages; this change does not change that behavior.

Local regression fixture: 5,000 other-author stories and 500 target stories, cursor/limit/owner-viewer evaluator parity, privacy projection, author block revocation, missing indexes, errors, unusual IDs and decoded JSON string/array collisions. Plans show author+ID range seeks and per-author exception seeks without temporary ordering. Local materialized candidates on the representative mixed-privacy test were bounded near the requested page; this is not production billed-read evidence.

Index cost was checked, not assumed free: on a local SQLite fixture with 5,000 standard stories and a subset of app indexes (including expiry indexes), dynamic VM steps before/after adding 0098 were insert 257/289, metadata update 383/445, expiry update 383/445, delete 217/249. VM steps are not D1 billed writes, and this fixture does not model all production indexes; the ordinary author index adds one entry per story while the exception index is sparse. Backfill is a one-time cost. Any production net quota benefit remains unmeasured.

Local validation before rollout: Node 310/310, Python 513/513, schema/migration/index-plan tests pass. A guarded rollout is prepared but must follow source CI. No Android APK is built by this change.
