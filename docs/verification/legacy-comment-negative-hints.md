# Historical comment route negative hints

The latest ranked database-wide 60-minute window showed the historical root-comment count query at **2,088 reported rows read / 522 executions**, alongside a larger engagement summary consumer. These are SQL analytics, not identified phone requests or billed-account totals. An aggregate-only preflight [45373421227](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45373421227) hit its 257-row cap and reported 514 rows read, so total historical comment volume is unknown. A per-comment route backfill was rejected rather than running an unbounded migration or creating several new rows per historical comment.

The new migration creates only one global invalidation epoch and three triggers on the existing canonical root-document table; there is no historical backfill. Every root-comment insert, relevant update, or delete bumps the epoch in the same database transaction; no ordinary post/user write updates the epoch. Rollover changes the random generation before resetting the revision. This adds an epoch write when historical root comments are mutated, and trigger-condition CPU on root-document writes; it does not claim zero write cost.

For an already-authorized visible feed engagement batch, an isolate can remember that a resource has **no raw historical route candidates**, independent of blocked authors, deletion flags and canonical shadowing. It never caches a visibility-filtered zero. A first-primary D1 session reads the epoch before the batch and another first-primary session rechecks it afterward whenever any hint was used. If the marker changed or cannot be confirmed, the full original grouped count is rerun; older schema or any optional-hint failure also uses the original logic. A cold batch still runs the same three indexed route selectors and returns an exact count plus an existence bit; it pays an additional epoch read. A warm, unchanged batch can skip those selectors for known-empty resources but pays two epoch reads. Hints are per D1 binding/isolate, bounded to 1,024 resource IDs, do not share user data, have no timer, and are not guaranteed to survive isolates or deployment.

The ordinary exact one-resource comment API and all canonical counts/ACL checks are unchanged. Race tests insert a matching legacy comment between epoch check and batch, verify a complete retry, and exercise later insert/delete, block/unblock, shadow, other bindings, missing schema, rollback and generation rollover. An actual Worker query test confirms two authorized feed pages reuse empty-route hints and a subsequent historical insertion is visible. SQLite plans retain the original three route indexes; the initial twenty-resource prototype generated a 41-bind, 71,318-byte statement, but this was not compatible with the production compound-select limit (see correction below). Local dynamic SQLite VM steps for old versus cold candidate-aware counts were 71/96 empty, 183/215 with one match, 1,164/1,241 with ten, and 109,074/114,101 with 1,000; warm hinted pages bypass those candidate statements. In a small SQLite fixture the epoch triggers changed ordinary post insert/edit/delete VM steps from 91/100/65 to 97/118/73 and historical comment insert/edit/delete from 145/205/116 to 181/250/154. These are CPU proxies, not D1 billed reads/writes. Cold paths and root-comment mutations can cost more; production benefit depends on actual repeat resources and isolate reuse, which are not yet measured.

Local Worker 319/319, Python 518/518, schema/migration/index-plan tests pass. Guarded deployment and CI are required. No APK or daily quota claim.

A separate local SQLite fixture with 1,000 historical comments and ten unrelated requested resources measured 647 VM steps for the original grouped count, 897 for the cold candidate-aware grouped count, and 10 per epoch query (two on a full warm hit, with no grouped count). This illustrates the cold/warm tradeoff, not Cloudflare billed-row savings or actual isolate hit rate.

## D1 compatibility correction

A read-only synthetic production SQL smoke [45376295927](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45376295927) found that **both** the old and candidate-aware 10- and 20-resource compound statements fail with `too many terms in compound SELECT`; 1–5 resources succeeded. This affects the afe8fd9 Worker: larger feed pages can fall back to the existing exact individual summaries, and therefore cannot be claimed to receive this batching/negative-hint optimization. The first local tests used a SQLite build with a higher limit and did not reveal this. At five synthetic absent resources, D1 reported 20 rows read for the old grouped query and 30 for the cold candidate-aware query; one epoch read reported one row. These are synthetic query metrics, not a measured workload benefit.

The correction divides missing resources into groups of at most five, while retaining one D1 batch/snapshot for all engagement statements and count groups. It validates every group's complete unique slots before publishing results or remembering hints; it maintains the original per-post fallback. An automated 20-resource test emulates the verified limit, tests a warm hit and old-schema fallback, and preserves per-resource counts. Deployment and real-traffic effects must still be verified; do not treat the original rollout as proof of savings.

The five-resource chunk correction passed local 321 Worker tests, 518 Python tests and schema/migration/index tests, then PR Worker [45376734605](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45376734605) and Android verification [45376734196](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45376734196). Code-only rollout [45376920062](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45376920062) at 5ea271e confirmed the singleton and three triggers, retained bindings, and passed health/auth checks. The synthetic SQL smoke verifies each five-resource query, not an actual authenticated production feed session; real hit rate, concurrency behavior on D1 and net quota impact are still unmeasured.
