# Feed interaction state lookup

A recent analytics-only window reported an unmapped `SELECT resource, … WHERE resource IN (…)` shape at 152 rows read / 72 returned across eight executions in five minutes. Source inspection identifies a matching Home engagement state lookup, but the redacted shape alone is not conclusive attribution. Fixed-vocabulary reporting labels were added to distinguish this family without printing SQL values; the aggregate is not device telemetry or billing proof.

The state table uses a text primary-key index: selecting both resource and state normally seeks the index and then fetches a table row for each hit. A narrow covering index `(resource,state)` enables the same batched state query to read both fields from the index. The code explicitly selects it and retains the original query only when the index is absent during a rolling deploy. Other storage errors preserve the existing fail-soft behavior for optional engagement; they are not reinterpreted as schema absence. Authorized posts, verified/staging/missing-state semantics, legacy reaction uncertainty, fresh state reads, and engagement summaries remain unchanged.

Local SQLite fixture with 10,000 markers and a ten-resource query (nine matches) showed the automatic primary-key plan used a non-covering index and 146 VM steps; the forced new covering plan used 136 VM steps. D1 billed rows are not VM steps, so a reduction is not yet proven. Additional index maintenance on a small representative SQLite fixture raised insert 25→122 steps, state update 27→128, and delete 16→112; all resource markers occupy one extra index entry. This is not a D1 billed-write estimate and does not include all production triggers. Creation/backfill has a one-time cost; no representative-day budget is certified.

An integration test exercises old schema, covering plan, exact result parity, per-viewer reaction summary, staging and unknown markers, a state change between requests, and storage failure. Local and CI validation and a guarded rollout must pass before deployment. No APK is built here.
