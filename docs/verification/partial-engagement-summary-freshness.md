# Partial engagement summary freshness

The comments detail bundle supplies reaction totals, not the post's complete comment count and preview. `acceptDetailTotals` previously called the same cache write as a full engagement GET, making an empty/partial summary appear fresh for two minutes and renewing older comment fields. This could suppress a needed later full read and show stale/missing comment information. The reaction-only detail response now updates the reaction fields without extending full-summary freshness; if no full summary remains (including independent LRU eviction), any orphaned freshness timestamp is removed. Existing fresh complete summaries still avoid an immediate GET. An in-flight full GET started before the partial update is invalidated through the existing generation/retry guard, rather than overwriting newer reaction state.

Android regression tests exercise an initially absent summary, orphaned timestamp, unchanged age of an existing complete summary, later expiry and refresh, and an older in-flight full response. This is a correctness change, not a proven reduction in billed reads: a later GET is intentionally retained when the full summary is absent or stale.

A follow-up audit found the same freshness error in optimistic reaction and reaction-only write acknowledgements. Those partial publications now preserve the existing complete-summary age. A full initial GET, recovery GET or old-Worker full acknowledgement can renew it only if the complete comment fields are present and the local mutation generation stayed unchanged in flight. Concurrent invalidations retain the need for a later refresh. Tests exercise an actual tap and acknowledgement near expiry, an initial full GET reuse, and concurrent invalidation. This follow-up requires its own Android CI verification.
