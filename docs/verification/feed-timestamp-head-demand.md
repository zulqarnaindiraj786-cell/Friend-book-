# Home timestamp feed head and hot exceptions

The analytics-only [45369407817](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45369407817) identified the existing posts feed exception query at 3,240 reported rows read / 3,240 returned / 90 SQL executions in its overlapping 60-minute window. It is a database-wide SQL shape, not an identified device or action. An aggregate-only [45369658739](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45369658739) inspected at most 129 existing exception rows through the existing index: 36 rows (25 text dates, 11 missing/null/bool, zero object/array or unusual IDs); D1 reported 72 rows read for that preflight. This snapshot can change.

The normal evaluator ranks timestamp dates above text, numeric, boolean and missing/null dates. The new narrow head path can therefore return a page without loading lower-ranked exceptions **only when** all of these hold: ordinary unfiltered post feed with timestamp order, no competing exceptional timestamp/map/array, and a full page of live-ACL-authorized timestamp posts. A new sparse partial index identifies competing high-ranked exceptions; its `NOT EXISTS` guard is part of each candidate SELECT. Timestamp/time-tie cursor seeks use the existing feed index, including a safe numeric lower bound that avoids scanning its null-time bucket. A local 1,000-string-date empty-head probe fell from 6,012 to 15 SQLite VM steps when this range was added; VM steps are not billed rows. If a candidate page cannot be filled, any high-rank exception exists, the query/cursor is unusual, 50 speculative candidates are exhausted, or the sparse index is missing, the prior complete exception/evaluator path remains authoritative. Permission failures do not grant access. No mirror, trigger, data deletion, or unrestricted authorization change is involved.

Tests compare owner/viewer pages, equal timestamps, mixed rank, denied rows and older cursors to the complete generic evaluator. They also cover exceptional Unicode/NUL/array/map/fractional records, an exception inserted between refill batches, current block changes, errors and older schema; a bundled engagement test keeps reaction/comment summaries intact. SQLite plans assert both time-and-ID seeking and the in-statement sparse exception check, without a tie-group sort. Lower-ranked exceptions are skipped only for a full eligible page; query LIMIT is not a billed-read guarantee.

A 5,000-post local SQLite write experiment with a subset of indexes measured dynamic VM steps before/after 0099: insert 258/322, metadata or timestamp update 433/559, delete 233/299. The index is sparse for ordinary timestamp IDs but its predicate still has CPU cost, and the fixture does not represent all production indexes. VM steps are **not** D1 billed writes. Index build is a one-time cost; production net savings are not yet established.
