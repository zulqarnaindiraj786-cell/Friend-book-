# Legacy notification recipient prefix: candidate retirement

The mixed 24-hour query-analytics report [45380671427](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45380671427) identifies genuine notification writes among its largest write shapes, including 3,449 reported canonical row-writes / 505 executions and a separate notification mirror-upsert shape at 1,121 / 165. Those shapes are not matched events or a direct billed-savings estimate. Delivery and mirror data must not be suppressed based on these totals.

The legacy notification mirror stores a recipient-only `idx_cf_legacy_inbox_recipient`; its exact expression and collection predicate are the leftmost key and predicate of the existing `idx_cf_legacy_notif_page` index. The proposed idempotent migration 0102 drops only that redundant prefix. It does not delete notification data, stop mirror writes or alter delivery, canonical indexes, either unread index, exceptions, or the ordered replacement. Rollback can recreate the old index from migration 0025. Current source does not pin the removed index; a history search found no earlier `INDEXED BY idx_cf_legacy_inbox_recipient` references, though unknown external SQL clients cannot be ruled out.

A 5,000-row SQLite fixture includes plain and Firestore-wrapped recipient encodings, mixed read state and other recipients. It proves identical recipient results with the replacement before/after retirement, a replacement index seek, unchanged row count, repeatable migration and successful rollback recreation. It observes one fewer SQLite `IdxInsert` opcode per legacy notification insert; this is structural local evidence, **not** measured Cloudflare billed writes. Existing actual Worker unread/recipient/ACL tests still run with the original indexes and with fallback indexes removed. Full local 324 Worker and 522 Python tests plus schema/migration/index checks pass.

Before any remote DROP, the separate read-only inspection verifies **exact** old and replacement DDL and an actual Cloudflare EXPLAIN recipient seek, and caps the legacy-notification size sample at 257. The guarded application would repeat DDL/plan checks and remove only the named redundant index; it must not run the full migration chain. Index DROP itself has an unknown one-time production cost and a rollback would rebuild it. No live mutation, proven production billed savings, APK or completed-day quota pass is claimed at this stage.
