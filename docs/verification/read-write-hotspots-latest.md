# Read/write hotspot check

Read-only Cloudflare verification [45411972297](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45411972297) failed the strict daily target. The latest partial account-wide day reported **468,950 reads and 8,674 writes**, above both the user's comparison baseline of 416,253 / 6,366 and the separate stricter 100,000 / 5,000 target. These are delayed, account-wide counters including earlier versions and administrative activity; they cannot identify a single app action or prove a matched before/after improvement. There is no complete representative day after the backend boundary or trace of the corrected installed app.

The analytics-only traffic report [45411972277](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45411972277) reported **2,373 reads / 48 writes** for the preceding 60-minute primary-database window, and **94,899 / 3,821** for the preceding 360 minutes. Windows overlap, are delayed and may be unrepresentative; the five-minute window had no observations. The 60-minute shape list contained 19 executions / 570 reads for the grouped legacy comment-candidate probe and 24 executions / 48 reported writes for a notification legacy-mirror upsert. These are SQL-shape totals, not a trace of one user's action or proof that the rows or notifications are duplicates. The six-hour write list is truncated; among the returned shapes are mirror inserts and per-device FCM claims.

The comment probe retains author blocking, deletion and canonical-shadow semantics; previously deployed epoch-validated negative hints can skip it for confirmed absent routes without caching comment data. The notification mirror maintains a separate legacy representation; create/read acknowledgements also have no-op and create-only protections. Removing these mechanisms or FCM claims based on aggregate shape counts could lose notification delivery, read state, or privacy. Existing receipt tests establish local transactional behavior and no-op retries, not production billing equivalence. No production D1 scans, data edits, deployment, APK build or PR merge were performed for these checks.

The branch includes additional Android foreground scopes and duplicate in-flight read suppression since the last installed APK. They do not affect an installed client until it is updated. Certification still requires the owner's representative 60-second device trace (fewer than 10 attempts, zero background attempts and zero identical same-millisecond duplicates) and actual daily usage below the stated baseline; these results do not meet or prove those conditions.
