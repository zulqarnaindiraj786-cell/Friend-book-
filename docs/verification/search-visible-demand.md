# Search demand and screen ownership

Search previously scheduled its debounced lookup even if the Activity stopped before the timer fired, and a scroll near the bottom advanced both people-prefix pagers and the post pager together. Typing also painted local feed matches through the ordinary FeedAdapter; card binding could fetch engagement, and setPosts could query missing authors before the debounced search ran.

Search now closes its pagers and cancels the debounce at stop, rejects late results through CursorPager generation/actor checks, and resumes via the existing cache-first head path only when visible. Account changes clear the previous account's displayed results and invalidate pending search. Typing previews use cache-only engagement and author data; disabling author lookups also invalidates a pending author callback. Once a real result page arrives, normal explicit visible-card engagement and missing-author reads resume. The page size is ten for each stream, prefetch is disabled, and people/posts have separate explicit More controls; scrolling one section no longer advances all three streams. Continuing a search after returning starts from its cached first page rather than preserving all previously paged rows.

Android full compile/JVM tests [45364409695](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45364409695) pass on `4e14170`. Actual Activity tests show that a stopped debounce cannot start a query, a resumed search makes one head demand per stream, late pages cannot reactivate a stopped owner, cache-only previews with missing authors do not query, and actor switch clears old previews. FeedAdapter tests exercise 100 suppressed local-preview author demands and a late author response after disabling. Python source-contract suite: 513 tests pass. Intermediate compile failures [45363792225](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45363792225) and [45364143572](https://github.com/zulqarnaindiraj786-cell/Friend-book-/actions/runs/45364143572) were test-code matcher/row-type errors, fixed without disabling tests; final Android suite passes.

No Worker or database schema changes, APK, or merge. The source is not yet installed on the existing APK. These tests establish the guarded paths, not a measured number of production D1 reads. Hashtag backend search still materializes all FTS matches before sorting; page-size ten is not proof of a bounded SQL scan. A safer ordered-token design must preserve exact tokenizer, privacy and deletion behavior while accounting for write amplification; no speculative per-tag trigger/mirror was deployed.
