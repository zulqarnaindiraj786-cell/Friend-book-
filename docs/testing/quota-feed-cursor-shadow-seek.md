# Feed/Reels page and shared shadow-lookup seeks

This Worker-only change retains all existing Feed/Reels page sizes, per-post ACL checks, canonical-over-legacy precedence, historical exception handling, sorting and cursor semantics. It does not change notifications, likes, comments, message data or schemas.

Two independently observed SQLite plan problems caused unnecessary reads:

* A cursor predicate on the compound expression index started from the newest feed row and walked past newer posts. For unfiltered Feed/Reels pages with a cursor, the Worker now seeks the equal timestamp rank and time on the existing index. A timestamp cursor also includes a bounded numeric-rank branch in the **same SQL statement**, so old numeric records remain visible when the cursor crosses the rank boundary. Each branch returns at most the original page window; the merged output remains limited to the original window. Author-filtered pages and unsupported cursors retain their existing path. Exceptions remain on the existing exceptional-data path.
* `markWindowShadows` checked up to 90 paths with `path IN (...) AND parent_path=?`; on the local D1 schema the planner selected the parent index and scanned hundreds of same-parent documents rather than probing those paths. The Worker now reads the parent with each path-key lookup and applies the same parent comparison locally. The helper is also used for user and live pages; chat and notification callers deliberately still accept any canonical parent. No result or privacy check is removed.

With 600 synthetic mixed canonical/legacy records per collection, a real Worker and Miniflare D1 schema through 0083, local page results matched the prior Worker for both posts and reels. First page was **500 reads / 0 writes / 12 statements → 25 / 0 / 12**; a timestamp middle page **860 / 0 / 12 → 51 / 0 / 12**; a rank-boundary page **2,228 / 0 / 16 → 104 / 0 / 16**; a numeric page **1,154 / 0 / 12 → 26 / 0 / 12**. Different mirror ratios, private content, exceptional data, page depth and planner behavior change the result; these are local D1 metadata, not billed production usage. Both changes can still read extra bounded candidates, particularly the numeric branch and parent-mismatch rows.

Automated tests compare indexed and generic pages for posts and reels across both ranks, ties, malformed timestamp exceptions, hidden rows, legacy-only rows, changed canonical privacy, stale mirrors, a canonical path under a different parent, and page sizes from 1 to 100. They assert primary-key and rank/time seek plans. Existing tests exercise 100-item legacy windows, pagination/refill, author filters, notification and live shadow behavior. Local suites passed 192 Worker tests against the staged production patch, and 196 with the separate unshipped friendship experiment in the working tree, plus nine schema/migration/index tests and 280 script tests. The network-disabled Worker replay passed 38,688 requests, 64 plans with no plan errors, and a wave of 200; SQLite statements/results are not D1 billed reads.

No D1 migration, production synthetic traffic, new Android AAB, or weakened ACL is required. Rollback is the previous Worker. Real account-wide savings, capacity, and device behavior remain unmeasured; an unlimited workload cannot be guaranteed to fit any fixed quota.
