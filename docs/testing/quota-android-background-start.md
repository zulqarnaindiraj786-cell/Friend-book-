# Android background process startup and presence

`Application.onCreate` also runs when a service or WorkManager wakes a killed process without any Activity. The prior unconditional idle callback started the current-user listener and online presence/heartbeat in that situation, even though the user was not using the app. The foreground lifecycle now initializes presence and ensures the profile listener on the first started Activity, while background-only startup retains Firebase/push initialization but does not start these jobs. Existing explicit sign-in, launcher and privacy-setting startup paths remain. Deferred offline and immediate privacy transitions remain in place.

When active status is disabled, `Presence.init()` formerly called `goOffline()` (which writes the current bound user's offline state) and then wrote the same user's offline state again. It now performs the second write only if `goOffline()` had to close a different bound account. Privacy is not delayed or suppressed.

Static wiring tests cover startup placement, push initialization, the offline callback and the different-account guard; the existing JVM presence tests cover socket lifecycle and write-policy transitions, but these tests do not prove real device/push behavior or quantify actual production savings.
