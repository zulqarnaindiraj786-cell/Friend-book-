# Owner-private payment lookup

Read-only analytics 44975596489 at 02:20 UTC reported a `payments` root fallback shape of 2,812 sampled rows read over 76 executions in its preceding 15 minutes. The analytics shape does not establish the user, filters, admin status, or caller; it cannot show what fraction the new path will improve.

Pending migration 0074 adds partial canonical and legacy user-ID indexes; this change has not yet been deployed to production. Non-admins can only read their own payments, so their query and count now seek that owner before applying the existing ACL and filters. Admins with a user-ID equality filter can also use the seek; unfiltered admins still see all permitted payments. Legacy primitive user IDs, REST envelopes and unusual string-value coercions retain compatibility, and any canonical row shadows the same legacy path regardless of owner. Missing indexes safely fall back during a rolling deployment. Index creation itself can incur production D1 writes; no backfill data or remote verification is needed.

Tests compare indexed results against forced full compatibility reads for 1,000 unrelated payments, conflicting owner metadata, stale shadows, Firestore envelopes and coerced values, admin access, private access, query limits and count. SQLite EXPLAIN verifies searches use both indexes. In a synthetic 1,000-user, 1,000-request owner-query replay, SQLite returned rows fell from 1,001,000 to 2,000; both used 3,000 statements and changed zero rows. Returned rows and SQLite changes are not Cloudflare billed reads/writes. The complete offline replay covered 30 workloads and 43 plans with zero plan errors; 175 Worker tests, 8 schema/migration/plan tests and 269 script tests passed. Actual production savings and overall quota compliance remain unverified.
