# Chat membership index, quota follow-up

The recent adaptive 15-minute analytics identified a canonical chat-participant join as a high-read shape (24,388 rows read across 119 executions); sampled analytics are not account dashboard totals or a controlled before/after. The badge and incoming-call paths still require the viewer's complete authorized chat set, and inbox pagination must sort authorized rooms before limiting. This optimization does not cap that result set and cannot guarantee any specific account-wide savings.

Migration 0073 adds an index on `(participant_uid, source, chat_path)`. Both membership joins explicitly seek the current user and selected store, rather than stepping over that user's memberships from both stores for each query. Existing room data, authoritative membership ACL, canonical-over-legacy precedence, unread totals and call detection are unchanged. If the index is not yet present, the Worker retries the old query. Privacy remains checked on stored room documents. The extra index can add storage and writes when memberships change.

For the production branch, the deploy workflow performs a single bounded aggregate count (maximum 5,001 entries) before applying the pending index. If the count fails or exceeds 5,000, it stops before applying migrations and does not deploy this Worker. This bounds index-build size, not the total daily quota; it does not guarantee remaining quota is sufficient. No per-user data is exposed and no synthetic production writes are issued.

A synthetic local SQLite experiment with 1,000 mirrored rooms returned the same 1,000 canonical rows. The join plan changed from seeking `participant_uid` alone to seeking both `participant_uid` and `source`; SQLite VM instruction counts changed from 20,011 to 14,011. These are local VM instructions, **not** D1 rows read or a live savings measurement. A test exercises index-present and index-absent behavior, legacy-only records, removed members, forged membership entries, batches over 90, and query plan selection. See `quota-chat-followup.md` for the preceding legacy-shadow fix and further limitations.
