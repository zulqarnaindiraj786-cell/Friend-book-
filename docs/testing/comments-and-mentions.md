# Chat-only tones, reusable comments and mentions — 2.8.21 (53)

## Requested behavior

- Only chat send/receive effects remain. Removed reaction/comment and Live gift effect call sites, decoding and WAV resources; gift animations, pricing, catalog and PK scoring are untouched. Existing background notification channel/chime remains distinct from foreground interaction effects. Two short original chat taps replace the rejected pops. These are WhatsApp-style approximations, NOT original WhatsApp recordings or a claim of matching them exactly. No actual phone listening test has been performed.
- Post detail and Reel comment composers now release their `busy` guard as soon as the unique local write has been queued, instead of holding it until an asynchronous Firestore server ACK (which may take indefinitely offline). Remote callbacks only notify/report failure; a delayed callback cannot unlock a different upload. Keyboard is not forcibly dismissed. Photo-upload guard remains until upload completes, then the composer can send the next comment. Every comment still has its own document ID and increment; offline writes retain normal Firestore synchronization limitations. No navigation out/reopen is required by the send state machine.
- Shared `Mentions.attach` offers bounded, debounced `@` display-name prefix search across users, not only friends. Bounded lower/title/upper capitalization variants match the existing user search schema; this is not a full-text or perfectly case-insensitive directory. Dropdown shows avatar/name and marks the post creator in blue. Selected names become blue identity spans. Only a selected suggestion establishes a UID link; arbitrary unselected `@text` is not guessed as an identity.
- Mentions are persisted as a bounded list of UID, exact label, UTF-16 start/end in comment parent maps, root/subcollection mirrors and post content. Repeated identical names can point at different UIDs. Exact-range/text validation rejects stale edited ranges. The shared post/comment renderer preserves clickable web links and blue profile links. Comment and post editing restore selected identity spans and save updated metadata; publishing snapshots mentions before media upload. Draft-restored plain text does not recover identities unless reselected.
- Post creator comments display a blue `◆ Creator` label and blue author name; verified-user tick stays independent. Tapping the author or a mention opens ProfileActivity with the UID, not a name search. Feed inline comments also render mention links and creator badges.

## Validation

Local source/wave guards cover chat-only playback, all three immediate chat send paths, fresh incoming gating, mute/background protections, removal of old sound assets, composer unlock before remote ACK, mention persistence/edit/render wiring and bounded/debounced lookup. Pure JVM MentionPolicy tests cover exact labels, stale/shifted edits, invalid paths/ranges, duplicate labels and Urdu text after emoji (UTF-16).

Device acceptance remains required: post 5+ comments consecutively on text/photo/video and reply threads without leaving, including slow/offline network and delayed ACK; send a photo then text and verify failures do not corrupt the next draft; test @ selections/deletion/insertion, repeated names, Urdu, creator suggestion/badge, multiple mentions and edits; tap persisted names after reopening and verify correct profiles; check dropdown position above keyboard, scroll/taps versus ordinary links, and safe chat audio on speaker/headphones. This change adds selected-profile linking, not a new mention-notification delivery guarantee.

## Reply-author auto mention — 2.8.22 (54)

Reply on a post/photo/video/reel comment now inserts `@Author Name ` directly into the comment composer with the comment author's UID, not the post owner's UID. Existing capture/persistence/rendering makes this part of the posted reply a blue clickable profile mention. The context chip remains supplementary. Repeated Reply replaces the prior generated target rather than stacking prefixes, preserves the drafted reply and manually selected mentions, and Cancel removes only an untouched auto-generated prefix. Edited text is never erased merely because it used to be an auto mention. A deleted/edited mention is not silently forced back at send time.

Four Robolectric tests cover visible body plus saved UID/clickable rendering, repeated/switch target with draft preservation, non-destructive edited-prefix cancellation and survival of manual mentions. Actual-device reply/send/reopen/profile-tap acceptance remains pending.
