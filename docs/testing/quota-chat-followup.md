# D1 quota: chat membership follow-up

A read-only adaptive analytics run around 00:41 UTC reported, in its 15-minute window, 24,388 rows read across 119 executions of a canonical chat-participant/document join, and other costs including notifications and point lookups. The five-minute window did not show that canonical join among its listed top query shapes. This is sampled/adaptive analytics and cannot be directly compared with account-wide dashboard totals or treated as a controlled experiment. The account dashboard screenshot showed 229.19k / 5M reads and 12.45k / 100k writes. The prior screenshot showed 196.44k reads and 11.35k writes; differences and timestamps are approximate and dashboard reporting may lag.

The chat list currently reads all eligible rooms for unread counts and incoming-call detection, and sorts authorized rooms before inbox pagination. The canonical join's size therefore cannot safely be reduced by placing a simple LIMIT on it. This change does **not** bound that join or claim to eliminate its 24,388-read spike.

The adjacent legacy membership join previously checked canonical storage once for every legacy room, even when its current room was already in the canonical membership result. It now reuses those canonical paths, then checks only unknown legacy paths in batches of at most 90. An unknown canonical path can represent a room from which the viewer was removed, so it still shadows the legacy mirror. Stored room membership and existing ACL checks remain authoritative. This is server-side and works for existing clients. It does not change the existing ordering or number of rooms, and does not require a migration.

A local SQLite integration test checks 120 mirrored rooms without per-mirror canonical shadow lookups, a removed participant, 92 legacy-only rooms, multiple batches, and a forged membership index entry. Full Worker tests and offline replay exercise the changed path. Local operation counts are not D1 billed rows; actual production saving is unknown, as are the causes of account-wide dashboard differences. No synthetic production traffic or write-verification is performed.
