# Friend-request create guard

A read-only query-analytics audit (44998861853) reported guard and presence activity, but these shared SQL shapes do not identify a specific feature or establish avoidable production writes. It also included earlier, one-off index-preflight scans. Do not infer a production before/after saving from that sample.

The `POST` friend-request create previously inserted and deleted a temporary social-guard row to check that no pending request exists for the same sender and recipient. The same canonical and legacy duplicate checks now run inside the canonical insert, in the same D1 batch as the legacy mirror. A duplicate forces the existing NOT NULL constraint to abort the transaction and returns 409. Canonical-over-legacy shadowing and validation remain unchanged. Other constraint/storage errors are not intentionally reclassified. This is a Worker-only change: no migration or Android bundle is required.
