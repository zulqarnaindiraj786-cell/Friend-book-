# Bounded feed/story loading — 2.8.24 (56)

Implemented cost-reduction stage, NOT 5,000-user certification:

- Home feed first batch and subsequent pages now 15 documents instead of100. First page is a one-shot get with an optional local-cache probe, not a continuously updating100-post listener. Pull-to-refresh fetches latest; other people's counters/posts no longer stream live into this feed. Own-action FastCache observers remain. Same-fragment return within2min retains successful state/cursor rather than refetching, provided account unchanged; explicit refresh remains available.
- Subsequent pages load near bottom on positive scroll or existing Load more button. One in-flight request per feed; refresh/session generations reject stale callbacks; account checks and onStop invalidation prevent stopped screens consuming data. Captured query ordering reused for all cursor pages, including document-ID fallback. Dedup at fetch and adapter boundaries. Filters apply on every page. Sparse/hidden pages do not automatically drain remaining database; user can explicitly load next page. Failed requests unlock retry. Refresh restarts a browsing window; it does not merge new head into old pages.
- Stories replace unbounded global realtime query with20-document expiry-ordered cursor pages. Horizontal rail scroll or More stories loads the next batch, allowing access beyond initial20 (no silent permanent cutoff). Lifecycle/session/account guards and dedup. Existing privacy, muted-author, blocked-author checks retained; Only me checks added. Returning to screen reloads first story batch; no realtime story streaming. Current backend story search is still global rather than personalized.
- Feed binding no longer fetches up to250 reaction subdocuments per post. Successful like/unlike no longer scan that collection either; counters/embedded own reaction plus optimistic observers are used. Explicit reaction-detail/reconciliation methods remain for existing callers.
- Standard Turbo/medium Cloudinary image delivery reduced780px ->600px, WebP + q_auto:good. Low mode480px retained; explicit high mode1200px and fullscreen/avatar modes retained. Does not change Firestore document-read billing, non-Cloudinary URLs or pre-transformed URLs.

Initial post query cap falls100 ->15 (85% fewer documents for a full first batch); this is NOT85% total Firebase bill reduction. Cache/server billing, other listeners, metadata stored inside posts and user activity determine actual usage.

Still outstanding before a scale claim: comment maps/document-size hotspots and duplicate comment persistence/listeners; paginated comment history + backward-compatible migration; inbox pagination, per-user friend graph/listener budgets; server-side fanout; security-rule deployment review; actual Firebase/RTDB/media quotas and cost monitoring. 5k registered/daily/concurrent users are different targets. Do not enable billing, delete data or claim load certification from this change.

Validation: Python source guards for first-page bounds, one-shot/no head listener, query/cursor reuse, loading locks, stale/account guard, dedup, story pages/more control and removed reaction scans. Existing regression suite retained; Android compilation/unit tests in signed CI. Real-device scroll/rapid refresh/offline/retry/filter changes/background/account switch/sparse pages, reaction UI consistency, story history navigation and actual before/after billed reads still need acceptance testing.
