# Mention-prefix follow-up

The earlier root-query analytics cannot identify the caller or cursor value; mention searches are a plausible source, not proven. The common mention query now has two additional indexed paths, using existing production indexes:

* Printable-ASCII prefix queries can stop after a bounded index head from each store when the page is full and its returned name/ID ordering can be proven equivalent to the original JavaScript evaluator. Hidden profiles, stale mirrors, unusual encodings and non-ASCII ordering may require the existing compatibility path. Extra pagination bounds retain the previous indexed query.
* Well-formed Unicode prefixes seek the full UTF-8 **prefix range**, which is a superset, rather than applying the U+F8FF JavaScript cursor as a SQLite bound. Existing JavaScript filtering, ordering and profile projection remain authoritative. Unpaired surrogates, control characters, oversized inputs and prefixes with no finite successor fall back. This path does not limit raw prefix matches, so a popular prefix may still read many rows.

Regression tests compare endpoint responses to forced compatibility queries for Arabic, Devanagari, Chinese, accented and combining names, emoji and astral boundaries, U+D7FF, maximum code point, hidden accounts, stale legacy shadows, Firestore envelopes, additional cursor constraints and Unicode cursor fallbacks. SQLite EXPLAIN confirms both indexes are searched. This is not a proof for arbitrary historical data or a production capacity measurement.

Offline actual-Worker replay: 1,000 synthetic users, 1,000 requests per prefix, no legacy mirrors. ASCII `user`: SQLite returned rows 1,001,000 before and 11,000 after, statements 4,000 before and 5,000 after. Unicode `آ`: SQLite returned rows 1,002,000 before and 2,000 after, statements 4,000 before and after. These are returned rows, **not billed D1 reads**. The full offline replay exercised 28 workloads, with 39 query plans and no plan errors. There were no changed rows for either search workload. Legacy distributions, large tie groups and visibility fallbacks can change costs; there is no evidence yet that this is the dominant production caller.

The same indexed Unicode-prefix superset now supports people-search and Live PK `displayName >= prefix` / `<= prefix+U+F8FF` filters. It also fixes an older ASCII-filter omission of legacy primitive `displayName` and non-text `stringValue` envelopes; canonical shadows and visibility still apply. Compared to forced compatibility queries, tests cover both filter and cursor forms across multiple scripts. A separate 1,000-request Arabic people-search replay changed SQLite returned rows from 1,002,000 to 2,000, with 4,000 statements and no changed rows in each run. Again these counts are not D1 billed reads; popular prefixes are not raw-row bounded. The expanded replay has 29 workloads and 41 query plans with no plan errors.

Current tests: 174 Worker tests, 8 schema/migration/plan tests and 269 script tests. Do not equate these local tests to complete app-wide quota resolution, live D1 cost, production user behavior, or D1 Free-plan capacity. A new signed Play AAB remains gated on representative live verification and unresolved other app-wide query/write shapes.
