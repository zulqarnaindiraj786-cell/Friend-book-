# Original social/chat/live sound effects — 2.8.20 (52)

Seven bundled, original deterministic PCM effects (22.05kHz mono): reaction pop, comment confirmation, message sent swoosh, foreground incoming ding, soft generic gift sparkle, synthetic lion roar and synthetic jet/fly-by. They are generated by `scripts/audio/make_effects.py`; no Facebook/TikTok recordings, downloaded audio, proprietary samples or new SDKs. Lion is a designed/synthetic roar, not a field recording. All assets decode below SoundPool's per-sample limit.

## Integration

- Post/photo/video/reel/comment reactions: immediate local action feedback after validation; unlike/remove stays silent. Server success still controls existing push notifications, not the tap sound.
- Comments/replies: one immediate shared CommentsEngine pop before the primary write, not again on fallback/mirror/success.
- Messenger text/photo, voice and sticker: one immediate local send-action sound when the validated payload is queued for commit, not after network acknowledgement. Media upload must finish before this send stage. This sound is NOT proof of delivery; failed/offline actions retain their existing error/queue UI. Server acknowledgements never replay it.
- Incoming messages: only fresh server-confirmed events after the initial server baseline while chat is foreground. Initial history, receipt edits, duplicates, pending/cache-only data and old events stay silent. Metadata-inclusive listeners allow pending writes to wait for acknowledgement.
- Open chat suppresses the matching FCM notification drawer/channel sound; its snapshot owns the in-chat ding. Other chats/background retain the existing friendbook notification chime, permission/channel/preferences and delivery limitations. This is not a push delivery fix or guarantee.
- Live: fresh confirmed gift packets play one mapped effect per event. Canonical giftId is included in packets; legacy emoji/name matching remains. Golden Lion -> roar; plane/airplane/aeroplane/jet IDs and existing Universe/rocket -> fly-by; other gifts -> generic sparkle. Current bundled gift catalog has Lion and Universe, not a separate purchasable Aeroplane item: no gift prices, balances, catalog items or PK scoring were changed. Existing banner/animation behavior remains. Cached/initial old gift packets do not play sounds.

## Audio behavior/settings

Uses bounded SoundPool (max 3 streams), existing Settings -> In-app sounds & haptics and Quiet mode, normal ringer mode, media volume and DND. Effects do not request audio focus or pause the existing live/video/voice player. Gift volume is modest; only one gift-effect stream at a time, with a 1.4s gift-lane cooldown to prevent rapid overlapping roars. UI effect cooldown 160ms. UI gain raised from 0.32 to 0.85; OS volume/mute still applies. Interaction assets now have a 1.5–2ms attack and 115–245ms total duration. Pool preloads at application startup and on resume; already-loaded effects execute directly on the main thread without extra Handler hops. First-load playback delayed over 120ms is discarded instead of playing late. Pending sounds stop when app loses foreground; resources release when UI hidden/low memory. No effects loop or intentionally play in background.

## Replaceable sound resources / Kotlin API (2.8.20)

`core/SoundManager.kt` is a Java-callable (`@JvmStatic`) facade over the existing shared SoundPool. Kotlin Android plugin 2.1.10 / JVM 17 enables this single native Kotlin entry point without migrating the Java app. Existing post/reel/comment and all three send hooks now call this facade; fresh incoming events call `playNewMessage`. No second pool or duplicate listener was added.

- `res/raw/like_pop.wav`: 200ms original soft rounded pop.
- `res/raw/comment_pop.wav`: 200ms original deeper (440Hz base vs 650Hz) pop.
- `res/raw/message_pop.wav`: 245ms original two-note incoming ding.
- Send confirmation retains the distinct short `sfx_message_sent.wav`; Live gift effects unchanged.

These are valid generated WAV files, not empty placeholders or WAV data disguised as MP3. Android exposes extension-independent IDs `R.raw.like_pop`, `R.raw.comment_pop`, `R.raw.message_pop`. To use licensed Pixabay MP3s, delete the corresponding WAV then add `like_pop.mp3`, `comment_pop.mp3`, `message_pop.mp3` with exactly those base names: do NOT keep both extensions for the same base name. Code needs no changes. Keep clips short, trim leading silence, retain any required licence/attribution and test safe gain on speakers/headphones. Running the waveform generator overwrites/restores the generated WAVs, so do not run it over MP3 replacements without removing or moving the MP3s first. No proprietary Facebook/Messenger recordings are bundled; exact platform audio equivalence is not claimed.
