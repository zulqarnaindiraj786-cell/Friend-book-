# Friendship acceptance: combine atomic guards

This Worker-only change combines the existing request/profile/friendship snapshot, duplicate-pair and requested-path absence assertions into one temporary social-guard row within the same D1 transaction. It does not remove any assertion, change authorization, limit friendship results, use the experimental friendship candidate index, or require a migration. An assertion failure still aborts the batch; a failed mirror or ledger write rolls back the entire acceptance. Legacy-only snapshots and existing friendship reconfirmation retain their checks. Unfriend is unchanged. The separate experimental indexed-candidate work is not part of this change.

With the real Worker and local Miniflare D1, migrations through 0083 and 200 unrelated mirrored friendships, a normal acceptance measured **1,415 reads / 70 writes / 23 statements before; 1,415 / 62 / 19 after**. Unfriend remained 417 / 37 / 16. This reduces eight local guard insert/delete writes and four statements, not the large friendship scan. These fixture-specific D1 metadata counts are not a production billing measurement or quota guarantee.

The staged-only production patch passed 197 Worker tests, nine schema/migration/index-plan tests and 280 script tests. The network-disabled replay passed 41,688 synthetic requests at waves of 200 and 69 EXPLAIN plans without plan errors. Its 100 acceptances used 1,900 statements and 1,100 changed SQLite rows, down from the previously documented 2,300 and 1,900; SQLite changes omit index maintenance. Actual Cloudflare D1 concurrency and billed savings require separate measurement.
