# Older chat history cursor seek

Android loads older messages with a descending `createdAt` cursor. The existing SQL's tuple predicate could walk all newer messages even though the ordered index existed. For the ordinary single-cursor descending query only, the Worker now seeks the cursor's rank and time with the existing index. A timestamp cursor also checks a bounded lower numeric-rank window in the same SQL statement, preserving historical numeric messages and exact timestamp/ID ties. Initial pages, ascending queries, gap queries, `limitToLast`, legacy-mixed rooms, malformed timestamps, membership ACL and unusual cursor shapes retain their existing behavior. There is no schema, Android or page-size change. If the index is unavailable, the previous non-hinted query remains the fallback.

Local Miniflare with the actual Worker, schema through 0083 and 600 synthetic messages returned identical IDs before and after. First page remained **13 reads / 0 writes / 5 statements**; middle older page **313 / 0 / 5 → 37 / 0 / 5**, timestamp/numeric boundary **513 / 0 / 5 → 27 / 0 / 5**, and older numeric page **558 / 0 / 5 → 14 / 0 / 5**. The extra lower-rank window can cost additional reads on some fixtures; these local D1 metadata are not actual billed production usage or a capacity guarantee.

Tests compare indexed pages against the generic evaluator across time ranks, duplicate times, varying cursors and sizes; assert the intended index seek plan; and verify forbidden actors, absent-index fallback, legacy bridge and malformed-time fallback. Existing chat tests also cover gap pagination and authorization. The staged Worker passed 193 tests; the working tree including the unshipped friendship experiment passed 197 Worker tests, nine schema/migration/plan tests and 280 script tests. A network-disabled SQLite replay passed 38,688 requests and 64 plans with no plan errors. The change requires no production synthetic messages, migration, new AAB, or write to user data.
