# Avoid reading chat mirrors already in the canonical membership window

The sampled 60-minute audit included the canonical chat membership join (5,989 rows read / 343 adaptive executions) and legacy membership join (16,812 / 268). These shared aggregates are not account billing and do not prove which screens or users caused them. The inbox and global badge need their complete authorized chat sets, so this change does not limit the set or suppress refreshes.

The Worker first reads the viewer's canonical membership window. If it is empty, it uses the previous legacy join. Otherwise it reads the legacy membership keys and fetches legacy documents only for paths not already present in the canonical window, in batches of at most 90. A canonical room outside that window can still shadow a stale legacy membership, so the existing shadow lookup and room ACL are retained. Malformed or forged membership entries do not grant access. There is no schema migration, production data deletion, intentional polling delay, Android release or new persistent cache.

In isolated Miniflare D1 with the actual Worker, existing indexes and synthetic rooms, an identical 201-room response (200 mirrored, one historical-only, one excluded stale room) measured **811 reads / 0 writes / 6 statements before, 613 / 0 / 7 after**. With 100 mirrored and 100 historical-only rooms the comparison was **811 / 0 / 207 versus 813 / 0 / 209**; with 200 historical-only rooms it remained **810 / 0 / 408**. The more legacy-only paths an account has alongside canonical paths, the more extra reads and statements the new path may perform; an entirely legacy-only account uses the old join. These are local D1 metadata, not production billing or capacity measurements. The membership reads are now sequential rather than parallel, and unknown legacy paths require another query, so actual request latency may increase; no real-device latency test has been performed. Roll back if this harms real use or if production measurements show no benefit.

Tests cover 120 mirrored rooms, over 90 historical-only paths, a removed member hidden by a canonical room, a forged canonical and legacy membership, a dangling membership, old-index fallback, historical-only accounts and inbox ordering. All 214 Worker tests and nine schema/migration/index-plan tests passed, as did ten relevant script tests. This is a specific read reduction, not a fix for all quota pressure: it saves no writes, and actual traffic mix and savings are unknown. No synthetic production traffic was sent.
