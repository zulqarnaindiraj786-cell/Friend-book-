# Cloudflare production readiness check

This marker file schedules a production Worker redeploy and read-only D1 diagnostics from the deployment workflow. The diagnostics inspect only aggregate resource counts and newest document IDs/owners; they do not copy, mutate, or delete Firebase or D1 user data. It also checks Workers KV namespace provisioning and the deployed `/health` response must report `views.kv: true`; namespace creation alone is not treated as proof that the Worker is bound. The current user reports that old users and records are still missing. Root collection queries now merge legacy app-document rows into the Firestore-compatible D1 query, with Firestore rows taking precedence for duplicate paths. A read-only collection-count comparison across both D1 stores checks users, posts, friends, friend requests, chats, messages, and notifications without returning user IDs or message content.
