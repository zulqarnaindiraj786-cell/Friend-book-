# Guarded indexed friendship duplicate checks

This change targets the full-table friendship duplicate and removal checks without dropping authorization, historical records or canonical-over-legacy shadowing. Migration 0084 adds two partial indexes for exceptional representations. Normal participant positions use the existing indexes. The Worker still applies the original duplicate/count predicates to candidate rows; the single batched duplicate assertion falls back to the original full scan whenever an unshadowed wrapped record contains dangerous malformed text. That probe runs inside the transaction, including for records raced in after the pre-read. Missing indexes or `FRIEND_GUARD_INDEXED` disabled fall back to the previous full-scan implementation. Exception-heavy data can still cost more; this is not a capacity guarantee.

Read-only run 44998087980 checked account-wide UTC daily adaptive analytics before examining tables: 941,667 reads and 41,412 writes at 2026-11-22 07:24:29 UTC. These analytics may lag and are not a transactional quota balance. Its bounded aggregate sampled the entire tables under a 50,001-per-table cap: 13,333 canonical and 10,011 legacy rows, including 484 and 123 friendship rows, with zero invalid outer JSON, zero draft-index exceptions and zero dangerous wrapped strings in that snapshot. D1 reported 23,345 reads for the check. Data can change after it; this is not a promise of migration cost or a billed-row forecast.

The production migration workflow independently rechecks account analytics below 3M reads/50k writes, caps each table at 50,001 rows, refuses truncation, a combined source size over 30,000, more than 1,000 exceptions, invalid JSON, missing or over-60,000 reported preflight reads, and rechecks account analytics again before migrations. The checks are conservative but cannot guarantee quota headroom under delayed metrics or concurrent changes. If they fail, no migration or Worker deployment occurs. Index build and maintenance use quota. Do not bypass the gate or drop/rebuild indexes casually.
