# Typing disabled; live/call repeated reads reduced

At the owner's request typing indicators are disabled, not chat messages, delivery receipts, notifications, voice/video calls or live streams. Server `TYPING_DISABLED=true` returns an inert `typing:false` to both old and new authenticated clients after validating the path, method and body. The answer is identical regardless of room existence or membership and cannot mutate or expose chat/account data; it therefore does not require the normal D1 account/membership lookup. Old clients can still issue HTTP requests every few seconds, but these disabled typing routes perform no D1 queries. Android v173 stops generating these requests and removes the chat typing UI/listener. Both status and typing maintenance are skipped while both are disabled; retained historical session rows are not deleted. Existing state is gated, not used. Re-enabling either later requires coordinating its server and client gates.

An independent recurring quota improvement keeps current privacy and renewal cadence: the call relay used to read the caller profile once for a separate status check and again to authorize both participants. The call authorization already requires active, unsuspended, unblocked current profiles for both participants, so the duplicate caller read is removed. Each renewal still rechecks the ledger, room and both profiles. In local SQLite tests a successful renewal now performs four lookups, including one per user; block, ban, suspension and end immediately deny the next renewal.

Live co-host and PK guest renewals also repeated room/user document reads within a single permission check. A request-local map reuses those documents only for that one check (co-host fixture 5 to 3 lookups, PK guest 7 to 4 including its PK lookup). Active PK room polling reuses room/account reads across the four authorizations within one HTTP request. Each new check or poll fetches fresh values; there is no cross-request or cross-renewal permission cache. Checks are not atomic against changes during one request, just as before, and changes are seen on the next renewal/poll. Local tests verify bans, suspension, blocks, kicks and ending rooms/calls; the bundled Worker was also exercised with disposable Miniflare D1 and real Durable Object sockets for calls, media, co-host and PK transitions. Existing 2-second/5-second lease and polling timings are unchanged, so this does not claim to eliminate all live/call reads. Counts are local lookup counts, not measured account billing.
