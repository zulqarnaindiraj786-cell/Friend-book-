# Reel playback cache and local preparation (candidate 170)

The immediate next visible holder may now prepare a MediaPlayer **only when the exact startup rendition is already fully cached**. It does not start the offscreen player, send view events, or make a new offscreen network request for preparation. The existing lookahead remains limited to one next Reel after first frame on validated, unmetered Wi-Fi, and remains disabled for mobile data/data saver. Pausing, detachment, recycling, a changed page or failed cache preparation retains normal cancellation and fallback. This can reduce preparation work on a cache hit; it cannot eliminate cold-network buffering or guarantee a target startup time.

Cache entries now identify the exact transformed URL (including quality) and use a new key namespace. Previously weak-link and standard Cloudinary renditions could collide, and a video post's local original could be stored under the R2 preview URL despite being a different file. The app no longer seeds unverified originals under remote rendition keys, and will not reuse old ambiguous entries. Existing cache files remain subject to ordinary eviction but may require one fresh download after upgrading. New Wi-Fi prefetch files are accepted only for a full HTTP 200 response with a known, matching Content-Length and within the existing per-file cap. Partial/cancelled files are not used for preparation. Full playback URLs and poster/streaming fallbacks remain unchanged; there is no backend, D1, ad, or privacy-policy change.

Unit tests cover rendition key separation, unknown/truncated download rejection and next-holder preparation eligibility, not actual Android MediaPlayer lifecycle or real-device timing. The existing script test for the 50dp banner was updated to check its extracted size method; 287 script tests passed. Test on real devices and mobile/Wi-Fi networks for cold and warm startup, rapid swipes, pause/background/resume, audio, cache eviction, data-saver, cached decoder errors, and post/reel playback. There is no measured production or handset speedup and no Facebook-equivalence claim.
