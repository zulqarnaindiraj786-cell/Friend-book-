# Reaction summaries and historical notification pages

Two Worker-only changes reduce unnecessary reads without changing page sizes, permissions, historical records, reaction writes or Android code:

* Reaction summary SQL previously joined the same `(resource,uid)` actor row once per nonzero reaction type. It now uses an uncorrelated scalar lookup inside the same SQL statement; the primary key guarantees at most one actor row. Type ordering, totals, null reactions and viewer-specific `mine` flags remain unchanged for full summaries, compact acknowledgements, Feed cards and comment pages that request reactions.
* For an older notification cursor with a **numeric** timestamp, numeric is the lowest supported rank, so an explicit rank/time seek cannot omit a lower rank. Both canonical and legacy stores use their existing recipient/unread indexes, with an unhinted fallback if the index is absent. Timestamp cursors, delta queries, initial pages, exceptional/wrapped records, cross-store shadow checks, and read/recipient authorization keep the prior paths. No new index or user-data write is required.

Using real Worker handlers and local Miniflare D1 with migrations through 0083, six reaction types and an actor who reacted, a full reaction GET and a comment page with reactions each went from **20 reads / 0 writes / 6 or 13 statements → 15 / 0 / the same statements**. An identical compact reaction retry went **18 / 0 / 7 → 13 / 0 / 7**; an actor without a reaction remained **14 / 0 / 6**. With fewer types, the reduction is smaller; with one type it is zero. Results and response bodies matched.

With 600 synthetic mixed canonical/legacy notifications, one numeric cursor returned identical IDs with **715 reads / 0 writes / 6 statements → 62 / 0 / 6** for all notifications and **485 / 0 / 6 → 49 / 0 / 6** for unread. Initial and timestamp-cursor queries were unchanged. Another all-numeric fixture gave **63 → 62** near the top and **421 → 62** mid-history for the all-notifications query. Actual savings depend on data distribution and planner behavior; local D1 counters are not account-wide billed usage.

The full timestamp-cursor seek was also explored locally but was not shipped: checking an extra historical numeric branch increased reads for some shallow pages. The retained implementation only changes numeric cursor paths. Regression tests cover six types, multiple viewers/resources, null and changed reactions, compact responses, batched Feed and comment summaries; they also compare all/unread notification pages against the generic evaluator across ties, ranks, stale mirrors, ownership changes, missing indexes, wrapped legacy rows, unrelated storage errors and delta ordering. Miniflare separately confirmed identical results when all four page indexes were absent. Local suites passed 195 Worker tests against the staged production patch, and 199 including the unshipped friendship experiment, plus nine schema/migration/index tests and 280 script tests. The network-disabled replay ran 41,688 requests, 69 plans without EXPLAIN errors, and a wave of 200; SQLite statements and returned rows are not billed D1 counts. Production deployment and read-only connectivity passed in run 44993622723; Worker validation passed in 44993622724 and Android compile/unit verification passed in 44993622751. Signed-candidate packaging was skipped. No production synthetic activity or new AAB was used. Rollback is the prior Worker; no migration is necessary.
