# Chat push burst follow-up

Read-only audit 44971224732 around 01:23 UTC reported a daily adaptive query aggregate of 154,747 rows read and 13,976 written for this database; this is not the account dashboard total. Its most recent five-minute results were comparatively quiet, including 288 rows read / 290 executions of preferred point lookups and nine rows written / two presence upserts. The top 60-minute shapes still include a previously reported 24,388 rows / 119 canonical chat-membership joins, but overlap older traffic, so they cannot establish a post-deployment rate or attribute the joins to push events. No production synthetic load was sent.

The current Main screen computes the unread badge and detects calls over every authorized room. A message FCM hint refreshes that global room query, as well as the open chat message listener. Every repeated hint in a burst could therefore repeat the complete membership query. The Android client now groups global room-list **message hints** for 500ms in a fixed, account-scoped window. The first hint sets the deadline and continuous traffic cannot postpone it. A hint arriving after the window opens a new window, including while a previous read is in flight. Open-chat message reads remain immediate; incoming calls still use their separate immediate authenticated room lookup. The visible inbox retains its existing separate debounce and committed local writes still invalidate normally. Account switches are checked before the delayed refresh; failed scheduling falls back to an immediate refresh.

The signed v2.10.26 candidate is a prerelease, not a store release. Only devices that install the new candidate benefit. It delays the global badge by up to 500ms for a message hint. The rate of duplicate message hints in production, and therefore actual savings, are unknown. A single message, ordinary user actions, missed/delayed FCM, open-room signaling, badge queries and notification events retain their existing costs and behavior. This does not cap complete membership joins or bound total Free-plan usage. Unit tests cover fixed windows, distinct rooms, account switches, event during refresh, invalid IDs and scheduler rejection. All reads remain authenticated and authoritative.
