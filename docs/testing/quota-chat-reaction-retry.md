# Avoid writing identical chat reaction retries

For a standalone PATCH to a canonical nested chat message, after existing authorization, a request containing only the actor's own `reactions`, `reactorNames` or `reactorPhotos` fields can skip the write when its computed document is byte-for-byte unchanged. Before acknowledging, a single fresh indexed SELECT compares the authorized room and message snapshots, including the message update time. Concurrent membership removal, message changes or deletion fail closed. Successful no-ops preserve the existing response shape and persisted update time. Changed reactions, other field edits, legacy-only rooms and batch requests keep their current paths. This does not change post or reel reactions, and is not a diagnosis of a particular device's reaction error.

An offline Miniflare actual-Worker fixture measured an unchanged repeated own reaction **6 reads / 5 writes / 4 statements** before and **5 / 0 / 4** after. A genuine first reaction remained **6 / 5 / 4**. Unauthorized changes, membership and message races, deletion, repeated removal, and legacy-room fallback are covered by unit tests; concurrent simulated actors preserved acknowledged edits. Full Worker tests passed 214, plus nine schema/migration/index tests. Local D1 metadata is not production billing. Production retry frequency and savings are unknown. No schema migration, APK change, synthetic production reaction or quota guarantee is involved.
