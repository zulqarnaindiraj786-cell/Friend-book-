# Friendship candidate-index experiment — historical working draft

A revised version was later deployed; see `quota-friend-index-guarded.md`. This file preserves the earlier unshipped experiment and is not the deployment record.

This was an offline prototype, not a production migration. `fixtures/friend_guard_exceptions_draft.sql` deliberately lives outside `cloudflare/migrations/`, so the normal deploy workflow will not apply it. The Worker changes and tests in the working tree are experimental; do not deploy or merge them as a completed quota fix. The prototype is disabled unless the Worker environment explicitly sets `FRIEND_GUARD_INDEX_EXPERIMENT=true`; when disabled it uses the original full scan without probing for indexes. When enabled but indexes are absent it also falls back to the full scan. No production SQL, synthetic app traffic, or AAB was generated for this experiment.

The prototype narrows candidates with both existing participant-position indexes and partial indexes for native objects, long arrays, Firestore envelopes, and legacy rows containing `fields`, then applies the original duplicate/count predicates. It preserves canonical-over-legacy shadowing and transaction-time checks. Tests compare native, long, object, wrapped, legacy and shadowed examples; test inserts racing historical duplicates before acceptance and removal, and confirm transaction rollback. These examples are not a proof of equivalence for every malformed envelope, particularly error behavior when `json_extract` sees malformed primitive values. Exception-heavy historical data can still require a large scan. More adversarial and Cloudflare-runtime concurrency testing is needed before release.

Local Miniflare with 200 unrelated mirrored friendships gave acceptance **1,415 reads / 70 writes / 23 statements → 31 / 70 / 24**, removal **417 / 37 / 16 → 25 / 37 / 17**. Statements include one index-availability query. An offline SQLite replay with the draft migration temporarily installed ran 38,688 operations; 100 acceptances used 2,400 statements and 100 removals 1,700, with changed rows unchanged from the previous implementation. It recorded 65 query plans. These are fixture-specific local measurements, not account-wide billed savings or a capacity guarantee.

Index creation is not free: creating the two partial indexes after seeding the above fixture reported **204 and 201 rows read**, respectively, even though no friendship was exceptional. Those numbers exclude an unknown production database size and do not establish actual D1 billing; inserts/updates to exceptional rows also maintain the indexes. A safe rollout needs an independently bounded estimate of both complete source-table scans, exception counts and index writes, as well as current available quota/headroom and a conservative abortable preflight. Production cardinality and remaining daily headroom are unknown. Do not place the draft in the migration directory or turn on production deployment until these questions, malformed-record equivalence, runtime tests and rollback are resolved. Dropping/rebuilding an index itself also costs resources.

A subsequent adversarial short-circuit test found a concrete difference in error behavior: with a malformed wrapped row and a matching native row, the original duplicate `EXISTS` can raise `malformed JSON` while the raw indexed candidate UNION can visit the match first and return true. Earlier differential tests materialized the full matching result and missed this order-dependent behavior.

The revised **still-unshipped** prototype probes indexed, unshadowed exception rows for dangerous wrapped text inside the same transaction as the duplicate guard. When one exists, it executes the original full-scan duplicate predicate, retaining its original error and ordering behavior; otherwise it uses indexed candidates. The atomic probe also covers invalid rows inserted after the initial pre-read. It does not change the existing pair-selection or unfriend predicates. Tests compare original and revised duplicate guards, first pair selection and duplicate counts over 1,800 randomized multi-row datasets with native, wrapped, malformed, shadowed and legacy records; 1,200 earlier single-row cases are also retained. Real Worker and local Miniflare separately checked malformed canonical and legacy rows inserted just before the batch, a long-array duplicate and a path collision: all returned 409 and rolled back. Two concurrent local acceptances produced one success and one conflict, correct counters and one ledger entry. This narrows the observed error mismatch but does not prove equivalence for every possible record or cloud concurrency case.

A separate no-migration variant reused existing participant indexes to enumerate exceptions. It was rejected: in local Miniflare an acceptance with zero unrelated friendships worsened from 15 to 27 reads, with 20 plain friendships went 155 to 147, and with 200 wrapped friendships worsened from 1,415 to 2,626; unfriend worsened by eight reads in those examples. It has not been staged or deployed. Its fixture-only gains do not justify those regressions.

Against the production Worker after acceptance-guard coalescing, local Miniflare with 200 unrelated mirrored friendships measured acceptance **1,415 reads / 62 writes / 19 statements → 33 / 62 / 20** and removal **417 / 37 / 16 → 25 / 37 / 17**. The extra statement checks index availability. The 1,000-account offline replay with indexed experiment enabled passed 41,688 requests in waves of 200 and 70 plans with no EXPLAIN errors; 203 Worker, nine schema/plan and 280 script tests passed. Counts are local and do not establish production billed savings. Two index builds still scan source tables; current billed headroom, maximum production scan cost and an abortable migration preflight are unknown. Do not deploy, enable the flag or move the draft SQL to migrations until those gates and rollback are reviewed.

Local verification: 196 Worker tests and nine schema/migration/index tests passed with the draft SQL outside the migration directory; 280 script tests also passed. A deterministic 1,200-case SQLite differential test compares both guard predicates and malformed-value errors across native, wrapped, long, scalar, object, shadowed and legacy shapes. The disabled path, missing-index path and unrelated-error propagation were tested. These local examples still do not prove all possible historical shapes or production migration cost. Reproduce the indexed offline replay with `QUOTA_EXPERIMENT_FRIEND_INDEXES=1 QUOTA_QUERY_PLANS=1 node scripts/loadtest/d1_quota_replay.mjs 1000 1`. No claim is made that the entire app's quota problem is solved.
