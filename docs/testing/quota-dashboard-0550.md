Reducing the limit to the displayed 15+ badge cap can miss notifications or leave unread items uncleared; do not do so without a replacement design and end-to-end tests. Current notification queries already choose the appropriate recipient/time/unread indexes in the local migrated schema. The displayed chat list and badge need complete authorized membership and call state; a blind LIMIT would miss unread counts or calls. Comment insertion and session transitions cannot safely be suppressed merely because their SQL appears among high-write shapes.

No extra D1 indexes, migrations, or synthetic production requests were run for this audit. Preserving behavior and privacy means no blanket claim that the quota problem is completely resolved. A stronger bounded-cost design would need carefully maintained per-user projections/deltas, atomic update and rebuild/reconciliation strategies, and tests for stale mirrors, membership changes, blocked users, incoming calls and unread transitions. Such a design would incur some additional write/storage costs and must be measured against actual production workload before deployment.
