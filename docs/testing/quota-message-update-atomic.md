# Atomic nested-message updates without temporary guard rows

For an existing canonical nested chat message whose authorized room snapshot is canonical, a standalone document update now compares both the exact message JSON and the room JSON inside one conditional D1 UPDATE. The authorization occurs first, unchanged. A concurrent room/membership change, message edit or deletion makes the update affect no rows and the request fails rather than overwriting data. Historical-only rooms, message creation, deletion, root messages, and batch updates retain their existing paths. A successful update returns the same response shape; no schema change, client change, new cache, or intentional freshness delay is introduced.

In local Miniflare with the actual Worker and migrations through 0083, one synthetic participant reaction update measured **8 reads / 7 writes / 6 statements** before and **6 / 5 / 4** after. The removed writes are the temporary snapshot guard and its deletion. The fixture also verified an unauthorized participant, a room-membership race and a message race, and concurrent actor updates preserved every acknowledged edit (one 200 and one 503 in that particular contention run, before and after). Offline SQLite tests exercise reaction add/change/remove, rejection of other users' reactions, Team-room authorization, membership/message/deletion races, and legacy-only room fallback. The full Worker suite passed 213 tests and nine schema/migration/index tests passed.

This path does not remove writes for actual reactions or cover every chat action. Production request frequency, billed-row savings, real device latency, and whether it resolves an individual user's reaction error are unknown. Miniflare counters are synthetic and are not account-wide billing. No production test messages or likes, index drops, or D1 migrations are required; rollback is the preceding Worker version. A finite free quota cannot cover arbitrary activity.
