# Status removal and read-path work in progress

This is not a production deployment or capacity certification.

* Android status/indicator implementation, socket, lifecycle calls, hidden dot and status views were removed. Chat read receipts, message delivery, live invites and call signaling remain. Old status profile fields are retained in stored documents and the Worker recognizes the old exact heartbeat shape to suppress unnecessary writes without discarding mixed profile edits.
* The Worker no longer routes the retired status endpoints (404, without D1), and scheduled cleanup no longer queries those tables. Video cleanup and broadcast push continue independently. Historical migrations remain intact; migration 0086 drops only the seven specifically named tables, with no replacement table. The deployment workflow requires explicit opt-in, bounded table inspection and conservative account analytics before applying it. No production table was dropped in this work.
* `D1DocumentStore` no longer schedules the visible-chat fallback (previously 5 seconds, backing off to 20 seconds while idle). On screen open and push it still fetches authoritative data; chat now has manual pull-to-refresh if a push is missed. Cached data is scoped by authenticated user. A missed push can leave chat stale until manual refresh, reopening, or foreground refresh. Feed and friend-request lists were already non-periodic. Feed is now 20 per cursor page, previously 5. Home's 120-second staleness threshold is checked when the tab becomes visible; it is not a timer poll. Live discovery still polls at 10–20 seconds, and active live/call signaling at 5 seconds, with error backoff, to preserve those features.
* The canonical-only schema/read-path redesign is **not complete**. Historical root and chat records still depend on legacy compatibility. In production follow-index preflight 44979510362, two legacy-only user paths existed at that point in time (`quota-follow-membership.md`). Removing the fallback without a verified backfill would hide data. Existing expression indexes and cursor seeks are not the requested physical author/from/to/time columns. A safe bounded backfill, concurrent-write handling, complete verification, and query/index migration remain to be designed and tested. Do not deploy a canonical-only read change until these have passed.
* Local tests: 219 Worker, nine schema/migration/index, and 297 Python tests passed. Android compile/unit runs 45019669723 and 45019863744 passed for commits e666f20 and 90228d9, respectively. A 20-card engagement-batching fixture also passed. The isolated retired-table test verifies repeatability and preservation of representative non-status tables. Tests do not establish real device behavior or billed usage.
* Existing local fixtures measured a 5-card feed query at 44 rows read and 0 written, a like at 7/4, a comment at 10/9 and a message-plus-room update at 4/10. These numbers do not cover a 20-card page, push, all screens, five users' activity, or account billing. No defensible new daily reads/writes forecast or <100k/<5k guarantee is established.
